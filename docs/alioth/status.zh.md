# 技术状况

[English](status.md) · 中文

Redmi K40 / POCO F3（`alioth`，骁龙 870 / SM8250）移植在 2026 年 11 月的状况。这里每一项「能用」都在手机上验证过，
数字都是在手机上测的。

## 启动过程

1. 在 Android 下 `adb reboot bootloader`，然后用 `fastboot boot` 启动一个镜像：里面是启动垫片、这台手机的 UEFI 阶段、
   我们的引导程序和手机的设备树。原厂 bootloader 从内存运行它，不写入任何东西。
2. 引导程序通过 UEFI 的 USB 设备协议提供 fastboot：先把系统镜像收进内存（`fastboot stage`，2.4 GB，25 MB/s 下约 97 秒），
   再收载荷：内核、根盘和启动参数。
3. XNU（`xnu-8796.121.2`，加上 HakiOS 补丁和这台手机的驱动）在 7 个核心上启动（`bootcpu=7 cpus=7`）。第 8 个核心留给
   引导程序，开发时它保持 USB 连接：内核日志、截屏、结束运行都靠它。发布版里 USB 控制器交给 iOS。
4. 根盘里是我们的程序、launchd 任务和手机的固件。系统镜像是从 IPSW 构建的原版 iOS 16.5（20F66，iPhone X）文件系统，
   只读挂载。数据卷是内存盘。
5. 一次运行结束时，内核交还硬件并回到引导程序；重启就回到 Android。

一键发布包用电脑上的脚本完成这些步骤；开发时一步一步来。

## 内核驱动

| 部分 | 怎么实现 | 状态 |
|---|---|---|
| 显示 | 1080 x 2400、120 Hz 的 DSI 视频面板。iOS 的画面直接交给显示引擎：VIG0 管线在显示保留内存里的两个扫描槽之间翻页，由引擎从 1125 x 2436 缩放（不经过 CPU 复制）。按面板的 TE（8.24 ms）节奏出帧。颜色校正模块（DSPP PCC）实现反转颜色、色彩滤镜和夜览。亮度用 DCS 命令调节。 | 能用 |
| GPU | 由内核自己启动 Adreno 650：GMU、SMMU 页表、环形缓冲区、来自手机固件的 SQE 微码；670 MHz。Mesa 的 freedreno 通过 msm 风格的接口使用它（显存、提交、fence、导入 IOSurface）。每个客户端有自己的 GPU 地址空间：执行某个客户端的命令前先等 GPU 空闲，再把 SMMU 上下文切到它的页表。 | 能用 |
| 触摸、按键、振动 | FocalTech 触摸控制器，支持多点触摸；PMIC 的电源键和音量键；振动马达 | 能用 |
| 声音 | 启动音频 DSP 并通过 APR 控制；两颗 CS35L41 功放；WCD938x 编解码器的麦克风走 SoundWire | 能用 |
| Wi-Fi | PCIe 和 MHI 连接高通 Wi-Fi 芯片，加载其固件，Linux 的 ath11k 跑在兼容层上；能连接 WPA2 网络，优先 5 GHz | 能用 |
| 蓝牙 | 921600 波特率的 UART HCI，加载固件和 NVM；上面是 iOS 自己的 bluetoothd | 能用，包括蓝牙音频 |
| 相机 | Titan 480 的 IFE-lite 通路写进内存，PM8008 供电；四颗传感器（IMX582 主摄、S5K3T2 前置、IMX355 超广角、S5K5E9 微距），颜色调校由 Android 的文件生成 | 能用；每次启动选一颗后置 |
| 手电筒 | PM8150L 闪光灯模块 | 能用 |
| 传感器 | 启动传感器 DSP（SLPI），通过 FastRPC 和它的传感器服务提供环境光、加速度计、陀螺仪、磁力计、旋转矢量、方向 | 能用 |
| 电池 | 电量计：电量和充电状态 | 能用 |
| USB | 设备模式的 DWC3：开发用串口，或者带苹果 usbmux 的 iPhone（配对、AFC） | 能用；运行中重新插拔正在修 |
| CPU | 7 个核心的调频和温控 | 能用 |
| 基带 | 外置的 SDX55，走 PCIe：它的引导程序在校验之后拒绝镜像 | 不能用 |
| GPS、NFC、指纹、距离传感器 | — | 还没开始 |

## 用户空间

- **OpenGL ES。** `EAGLContext` 是我们自己实现的，基于 Mesa（OSMesa 加 freedreno），既给系统合成（backboardd）用，也在 App
  自己的进程里给 App 用：ES 1、2、3，`CAEAGLLayer` 的画面以 IOSurface 零复制交给合成器，共享组，GLKit 的纹理加载，
  Core Video 纹理缓存。iPhone 独有的格式也补上了：PVRTC 纹理由处理器解码，提供 APPLE 多重采样和 BGRA 扩展。
  出帧上限每秒 62 帧，和 60 Hz 的 iPhone 一样。
- **注入 SpringBoard、backboardd 和 App 的库**填补 iPhone 和这台手机之间的差别：把环境光传感器作为 HID 服务提供给
  自动亮度，为 Core Motion 和 Core Location 提供姿态和朝向（真北由 WMM2025 磁场模型算出），自动旋转，相机传感器选择。
- **不需要签名的 App** 通过 LaunchServices 安装：每次启动由电脑安装，或用手机上的安装器。
- **辅助功能**：系统镜像里带着 iOS 的辅助功能模块，所以辅助触控、粗体文本等都能用；显示相关的颜色设置（反转颜色、色彩滤镜、夜览）通过帧缓冲驱动交给显示引擎的颜色校正，和真 iPhone 一样。
- **USB 当作 iPhone**：我们的 usbmux 守护进程把电脑的连接转给 lockdownd 和它启动的服务。

## 已知问题

| 问题 | 已知的原因 |
|---|---|
| 没有 Metal | 没有发布 Metal 设备。计划见下。 |
| 什么都不保存 | 数据卷是内存盘：重启后设置、照片、App 都会消失。 |
| GPU 卡死后屏幕停住 | 还没有卡死检测和 GPU 复位。 |
| 熄屏后仍然温热 | 处理器会降频，但屏幕链路和 GPU 一直开着；GPU 还没有功耗管理（固定频率）。 |
| 重新插拔 USB 后 | 已修复：拔线瞬间 select() 的竞争会让内核崩溃；重新插上后控制器的 EP0 不应答或应答出错（现在电脑反复复位无果时会从头重启控制器）；旧会话的数据和等待中的写入会漏进新会话。已用端口自己断开重连测试（启动参数 usb_bounce，每次运行三次）；这个版本还要再手动拔插确认。 |
| Safari 不能选照片 | 照片选择器在这里打不开相册；还没查原因。 |
| 游戏每次启动都问能不能发通知 | 答案保存在数据卷里，而数据卷在内存里。 |
| 辅助触控的「主屏幕」没反应 | 悬浮按钮、菜单、控制中心都能用；「主屏幕」这个动作在这里还没接上。 |

## 接下来

- **功耗**：GPU 调频和空闲断电，熄屏时关闭屏幕链路，用中断代替轮询。
- **流畅度**：第三个扫描槽，交换画面时不等翻页完成。
- **GPU 稳定性**：每个显存对象的 fence、fence 中断、卡死恢复。
- **Metal**（估计 2.5–3.5 个月）：在加速器服务上发布 Metal 插件，用 metal2vulkan 把 Metal 转成 Vulkan，再交给 Mesa 的
  Turnip 驱动，使用同一套内核接口。第一个目标：拿到 Metal 设备并画出一个三角形；然后是 App。
- **持久安装**（估计 3–5 周，另加启动菜单）：内核里已经有 UFS 代码；难点是数据卷需要可写的文件系统，以及手机存储上的
  空间，这意味着要重新分区——只有在机主明确同意并完整备份后才会做。
- **iOS 26**（已调研；估计 4–6 个月才能达到现在的完成度）：内核源码已经发布，但 iOS 26 全部是 arm64e，而这颗 CPU 没有
  指针认证，所以用户空间要离线转换；新界面要流畅需要 Metal。
