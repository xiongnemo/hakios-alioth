# 技术状况

[English](status.md) · 中文

Redmi K40 / POCO F3（`alioth`，骁龙 870 / SM8250）移植在 2026 年 11 月的状况。这里每一项「能用」都在手机上验证过，
数字都是在手机上测的。

## 启动过程

1. 在 Android 下 `adb reboot bootloader`，然后用 `fastboot boot` 启动一个镜像：里面是启动垫片、这台手机的 UEFI 阶段、
   我们的引导程序和手机的设备树。原厂 bootloader 从内存运行它，不写入任何东西。
2. 引导程序通过 UEFI 的 USB 设备协议提供 fastboot：先把系统镜像收进内存（`fastboot stage`，2.6 GB，25 MB/s 下约 104 秒），
   再收载荷：内核、根盘和启动参数。
3. XNU（`xnu-8796.121.2`，加上 HakiOS 补丁和这台手机的驱动）在 7 个核心上启动（`bootcpu=7 cpus=7`）。第 8 个核心留给
   引导程序，开发时它保持 USB 连接：内核日志、截屏、结束运行都靠它。发布版里 USB 控制器交给 iOS。
4. 根盘里是我们的程序、launchd 任务和手机的固件。系统镜像是从 IPSW 构建的原版 iOS 16.5（20F66，iPhone X）文件系统，
   只读挂载。数据卷是内存盘。
5. 一次运行结束时，内核交还硬件并回到引导程序；重启就回到 Android。

一键发布包用电脑上的脚本完成这些步骤；开发时一步一步来。

## 内核驱动

| 部分 | 怎么实现 | 状态 |
|---|---|---|
| 显示 | 1080 x 2400、120 Hz 的 DSI 视频面板。iOS 的画面直接交给显示引擎：VIG0 管线在显示保留内存里的两个扫描槽之间翻页，由引擎从 1125 x 2436 缩放（不经过 CPU 复制）。按面板的 TE（8.24 ms）节奏出帧。颜色校正模块（DSPP PCC）实现反转颜色、色彩滤镜和夜览。亮度用 DCS 命令调节。熄屏时用 DCS 命令让面板睡眠，出帧的客户端随之等待。 | 能用 |
| GPU | 由内核自己启动 Adreno 650：GMU、SMMU 页表、环形缓冲区、来自手机固件的 SQE 微码；370–670 MHz，每 50 ms 按 GPU 的忙碌时间选一档，向 GMU 投票。Mesa 的 freedreno 通过 msm 风格的接口使用它（显存、提交、fence、导入 IOSurface）。每个客户端有自己的 GPU 地址空间：执行某个客户端的命令前先等 GPU 空闲，再把 SMMU 上下文切到它的页表。 | 能用 |
| 触摸、按键、振动 | FocalTech 触摸控制器，支持多点触摸；PMIC 的电源键和音量键；振动马达 | 能用 |
| 声音 | 启动音频 DSP 并通过 APR 控制；两颗 CS35L41 功放；WCD938x 编解码器的麦克风走 SoundWire | 能用 |
| Wi-Fi | PCIe 和 MHI 连接高通 Wi-Fi 芯片，加载其固件，Linux 的 ath11k 跑在兼容层上；能连接 WPA2 网络，优先 5 GHz | 能用 |
| 蓝牙 | 921600 波特率的 UART HCI，加载固件和 NVM；上面是 iOS 自己的 bluetoothd | 能用，包括蓝牙音频 |
| 相机 | Titan 480 的 IFE-lite 通路写进内存，PM8008 供电；四颗传感器（IMX582 主摄、S5K3T2 前置、IMX355 超广角、S5K5E9 微距），颜色调校由 Android 的文件生成 | 能用；每次启动选一颗后置 |
| 手电筒 | PM8150L 闪光灯模块 | 能用 |
| 传感器 | 启动传感器 DSP（SLPI），通过 FastRPC 和它的传感器服务提供环境光、加速度计、陀螺仪、磁力计、旋转矢量、方向 | 能用 |
| 电池 | 电量计：电量和充电状态 | 能用 |
| USB | 设备模式的 DWC3：开发用串口，或者带苹果 usbmux 的 iPhone（配对、AFC） | 能用，运行中拔插数据线也能恢复 |
| CPU | 7 个核心按负载调频（每 20 ms 一次，触摸时立刻升满）和温控 | 能用 |
| 基带 | 外置的 SDX55，走 PCIe：通过 PMIC 和 GPIO 上电，经 MHI 的 BHI 送入引导程序（要先打开 MSI，否则它的 PBL 拒绝镜像），然后 Sahara（12 个镜像）、进入 mission mode、QRTR（64 个服务）、应答它向 AP 要配置文件的 TFTP、DMS（读 IMEI，不进任何日志）、上线。一个 launchd 服务代替 CommCenter 回答 CoreTelephony，所以「关于本机」显示 IMEI，设置里有「蜂窝网络」。启动参数 `dt_baseband=1 mdm_step=6 mdm_msi=1 mdm_loc=1 mdm_opmode=0 mdm_listen=86400`；需要这台手机的基带分区和小米 ROM 里的基带配置，kit 打包时还不会复制它们 | 不插 SIM 卡时能用 |
| GPS | QMI LOC：自己开一个 GNSS 会话（GPS、北斗、GLONASS、Galileo、QZSS），注入时间、XTRA 星历和 Wi-Fi 粗定位；定位结果交给 iOS 的定位服务（CoreLocation 的模拟定位通道），卫星数据通过 `sysctl kern.hakios.gnss` 给 App。第一次定位：没有辅助 716 秒，全部辅助 41–63 秒 | 能用 |

| USB 主机（OTG：键盘、鼠标） | — | 尚未开始：没有主机控制器驱动和 USB 主机协议栈，按键事件也还进不了 iOS（[issue #1](https://github.com/xiongnemo/hakios-alioth/issues/1)） |

## 用户空间

- **OpenGL ES。** `EAGLContext` 是我们自己实现的，基于 Mesa（OSMesa 加 freedreno），既给系统合成（backboardd）用，也在 App
  自己的进程里给 App 用：ES 1、2、3，`CAEAGLLayer` 的画面以 IOSurface 零复制交给合成器，共享组，GLKit 的纹理加载，
  Core Video 纹理缓存。iPhone 独有的格式也补上了：PVRTC 纹理由处理器解码，提供 APPLE 多重采样和 BGRA 扩展。
  出帧上限每秒 62 帧，和 60 Hz 的 iPhone 一样。
- **注入 SpringBoard、backboardd 和 App 的库**填补 iPhone 和这台手机之间的差别：把环境光传感器作为 HID 服务提供给
  自动亮度，为 Core Motion 和 Core Location 提供姿态和朝向（真北由 WMM2025 磁场模型算出），自动旋转，相机传感器选择。
- **不需要签名的 App** 通过 LaunchServices 安装：每次启动由电脑安装，或用手机上的安装器。
- **辅助功能**：系统镜像里带着 iOS 的辅助功能模块，所以辅助触控、粗体文本等都能用；显示相关的颜色设置（反转颜色、色彩滤镜、夜览）通过帧缓冲驱动交给显示引擎的颜色校正，和真 iPhone 一样。
- **USB 当作 iPhone**：我们的 usbmux 守护进程把电脑的连接转给 lockdownd 和它启动的服务。

## 已知问题

| 问题 | 已知的原因 |
|---|---|
| 什么都不保存 | 数据卷是内存盘：重启后设置、照片、App 都会消失。 |
| GPU 卡死 | 能检测并恢复（`gpu_recover=1`，日常默认）：GPU 复位，画面继续。 |
| 熄屏时的功耗 | 面板睡眠，处理器和 GPU 降到最低频率，但 GPU 还没有断电，显示引擎的时钟也还开着。 |
| 重新插拔 USB 后 | 已修复：拔线瞬间 select() 的竞争会让内核崩溃；重新插上后控制器的 EP0 不应答或应答出错（现在电脑反复复位无果时会从头重启控制器）；旧会话的数据和等待中的写入会漏进新会话；另外大约一半的情况下，两个方向之一的第一个包会被当成重复包丢掉，因为数据端点沿用了上一个会话的 DATA0/DATA1 翻转位（现在每次选配置都会重新初始化端点）。已在测试版和正式版里手动快拔、慢拔验证：插回约 10 秒后电脑重新列出 iPhone，配对仍然有效。 |
| Wi-Fi 偶尔连不上 | 一天的多次启动里出现过一次：路由器反复以 reason 6（“收到未认证设备的二类帧”）把手机踢下线，整次运行都没联网。现在会自己重试这个网络（5、10、20、40、60 秒后，之后每分钟一次），断线后 2 秒重连。 |
| Wi-Fi 收比发慢 | 路由器发给手机时只用一路空间流：我们的关联请求说的是“只有一路接收”（SM 省电为 static，即驱动原样给的值；Linux 的 mac80211 总会改写它）。`wifi_mimo=1` 改成“关闭”，路由器就用两路。剩下的差距是网络本身的：同一台手机的 Android、同一块芯片、同一个路由器，收 185–245、发 472–483 Mbit/s，比例一样；接收时各核心约 90 % 空闲。 |
| GPS 拿不到 Wi-Fi 粗定位 | 从 11 月 21 日起 8 次开机里有 7 次粗定位被拒（定位服务刚打开时 locationd 会收回这个 bundle 的授权；有一次自己恢复了），第一次定位没有起点。`gnss_seed_auth=30`（默认关）先等定位服务打开、被收回就再授权：粗定位（±35 米）能送到调制解调器。 |
| 设置 > 通用 > 法律与监管、中文键盘会崩溃 | 已在系统镜像里修复（11 月 23 日）：法律文档（`/System/Library/ProductDocuments`，7 MB）和中文键盘的语言数据（zh-Hans 的 LinguisticData，116 MB）之前没放进镜像。现在拼音有候选词和联想。 |
| 游戏每次启动都问能不能发通知 | 答案保存在数据卷里，而数据卷在内存里。 |
| 辅助触控的「主屏幕」没反应 | 悬浮按钮、菜单、控制中心都能用；「主屏幕」这个动作在这里还没接上。 |

## 接下来

- **在命令流里切换 GPU 地址空间**：现在每次切到另一个 App 的页表都要先等 GPU 空闲，并且持有 GPU 锁；改在命令流里切换
  （CP_SMMU_TABLE_UPDATE）就不用等了。
- **功耗**：处理器核心的深度空闲状态（PSCI CPU_SUSPEND）已经写好（`cpu_suspend=MASK`，默认关闭），等第一次启动验证；
  熄屏时仍约 375 mA。
- **Wi-Fi**：WPA2 企业网（802.1X、eduroam）已经写好，走 iOS 自己的 eapolclient，正在真实网络上试；镜像里的网络文件现在
  可以写最多四个网络，按顺序尝试。
- **持久安装**：暂缓。内核里已经有 UFS 代码；难点是数据卷需要可写的文件系统，以及手机存储上的空间，这意味着要重新
  分区——只有在机主明确同意并完整备份后才会做。
- **更新的 iOS**：暂时留在 16.5。别的项目里 iOS 17 和 18 能在没有指针认证的 CPU 上跑，但在这类手机上还没有一个同时有
  Wi-Fi、蓝牙和稳定的设置。
